# Cursor Rules — Senior Discipline Edition

## Branching
- No direct commits to `main`.
- All work must occur in feature branches:
  - `feature/*`, `fix/*`, or `chore/*`.

## Testing
- Every contract in `contracts/*.json` must have a corresponding test in `tests/`.
- Workers **MAY NOT** write tests for their own modules.
- Only Tester agent can validate and mark contracts as complete.

## Code Formatting
- All code must pass:
  - `black --check .`
  - `isort --check-only .`

## Linting
- All code must pass `flake8` (or ruff).
- No unused imports, undefined variables, or shadowed names.

## CI Enforcement
- All pushes go through GitHub Actions workflow (`.github/workflows/ci.yml`).
- Merges to `main` are blocked unless:
  1. Formatting check passes
  2. Lint check passes
  3. Tests pass
  4. Contract coverage check passes
  5. Tester approval is present

## Separation of Concerns
- Workers only implement modules in their assigned directories.
- Workers **MUST NOT** modify unrelated files.
- All contracts define their allowed files — deviations = failed PR.

## Security
- No `.env`, keys, or secrets in repo.
- Secrets are injected via GitHub Secrets or MCP servers.
